# 长篇小说工作流 UI 入口与页面设计规格

**目标：** 为现有小说工作流骨架规划可落地的 UI 入口和页面结构，确保既能复用 SillyTavern 当前聊天、角色卡、World Info、memory 和 vectors，也能完全脱离当前聊天，从 0 开始创建、维护和生成一部长篇小说。

**架构：** 第一版采用扩展内独立小说工作台。小说项目是独立内容空间，当前聊天只是可选素材源，不是工作流前提。UI 使用 SillyTavern 现有扩展系统、魔杖菜单、右侧抽屉、弹窗、`getContext()` 和 `/api/novels` API，不新增独立站点路由。

**技术栈：** SillyTavern browser ESM extension、现有扩展 manifest、`public/scripts/st-context.js#getContext()`、`/api/novels`、`src/novels/*`、现有角色卡与 World Info API、Jest、Playwright。

---

## 设计原则

### 独立小说项目优先

小说工作流的主路径必须支持空白项目。

用户可以在没有当前聊天、没有已选角色、没有 World Info、没有 memory/vector collection 的情况下创建小说项目。项目创建后，用户可以在项目内手写设定、角色、地点、组织、物品、主线、支线、卷纲、章纲和场景。

### SillyTavern 资产是可选增强

当前聊天、角色卡、World Info、memory、vectors 和 chat metadata 都是可选素材源。

这些资产可以被引用、导入或绑定，但不能成为项目可打开、可编辑、可写作的必要条件。项目动态状态默认保存在小说项目目录中，不自动写回源角色卡或源 World Info。

### 主聊天区不被替换

小说工作台作为扩展 UI 运行。用户可以从魔杖菜单或右侧抽屉打开工作台，但主聊天 UI 仍保持可用。后续生成可以复用当前模型设置和 SillyTavern 生成能力，但 prompt 和上下文来源应来自小说项目本身。

### 页面覆盖已实现能力

当前提交已经实现的是最小骨架，不是完整小说 IDE。UI 设计必须覆盖这些已实现能力：

- 扩展 manifest 和 `index.js` 初始化。
- `/api/novels` 私有路由挂载。
- 小说项目 ID 安全校验。
- 小说项目路径规则。
- `project.json` 最小读写。
- 大纲模板推荐。
- 主线必填校验。
- 支线可后补。
- 卷纲、章纲、场景状态壳。
- 章节审核状态壳。
- 上下文 included/excluded/used 预算结果。

## 入口设计

### 入口 1：扩展魔杖菜单

在 SillyTavern 扩展魔杖菜单中增加 `Novel Workflow` 入口。

点击后打开小说工作台。如果用户没有项目，默认进入“我的小说 / 新建小说”页；如果存在最近项目，默认进入最近项目总览。

该入口是全局入口，不依赖当前聊天。

### 入口 2：右侧抽屉工作台

在右侧抽屉中提供小说工作台容器。工作台可以常驻、折叠和切换内部页面，适合写作时频繁查看纲要、上下文和草稿。

右侧抽屉内页面不应使用大型营销式布局，应使用密集、可扫描、偏工具型的操作界面。

### 入口 3：当前聊天导入入口

当前聊天相关入口只作为导入路径。

可放在工作台的“新建小说”页和“项目总览”页中，名称为“从当前聊天导入”。它可以读取当前聊天的角色、世界书、metadata 或历史摘要，但不能改变空白创建的默认路径。

## 新建小说页

### 目标

让用户从 0 创建项目，并明确选择是否复用现有 SillyTavern 资产。

### 创建方式

#### 空白小说

最小字段：

- 小说标题。
- 项目 ID。
- 类型或题材。
- 简介。
- 必需主线。
- 初始写作目标。

空白小说不要求角色卡、World Info 或当前聊天。保存时使用当前已实现的项目 ID 校验和项目写入能力。

#### 从模板开始

用户选择题材和关键词，页面调用模板推荐逻辑，展示推荐模板。

第一版已实现的模板推荐能力至少覆盖：

- 升级流/成长流。
- 多线并进流。

后续可以扩展为权谋、悬疑、副本、感情线、爽文打脸等模板。

#### 从 SillyTavern 资产组装

用户可选：

- 角色卡。
- World Info。
- memory collection。
- vector collection。
- 当前模型与预设。

选择后只建立引用或项目内导入副本，不自动改写源资产。

#### 从当前聊天导入

用户可选从当前聊天导入：

- 当前角色或群组成员。
- 当前绑定 World Info。
- chat metadata。
- 最近聊天摘要。
- 当前 extension prompts。

如果没有当前聊天，该选项显示不可用，但不影响其他创建方式。

### 校验

- 项目 ID 必须通过 `isValidNovelProjectId()`。
- 主线不能为空。
- 标题不能为空。
- 模板和资产绑定均可为空。

## 我的小说页

### 目标

作为小说项目的首页，用户可以打开已有项目或创建新项目。

### 功能

- 列出本地小说项目。
- 显示标题、题材、最近更新时间、当前卷章、草稿状态。
- 提供打开、重命名、导出入口。
- 显示 `/api/novels` 可用状态。

### 当前实现覆盖

当前后端只有 `/api/novels` 204 健康响应和 `project.json` 读写 helper。第一版 UI 可以先接入健康检查和基础项目保存，项目列表 API 需要后续补齐。

## 项目总览页

### 目标

显示一个小说项目的全局状态。

### 区块

- 项目标题、类型、简介。
- 当前进度：卷、章、场景。
- 主线状态。
- 最近草稿。
- 最近审核状态。
- 已绑定素材源。
- 上下文预算摘要。

### 与当前聊天关系

总览页可以显示“未关联聊天”或“已关联聊天”。未关联是正常状态，不是错误。

## 设定库页

### 目标

支持用户在项目内从 0 手写小说设定。

### 内容类型

- 世界规则。
- 能力体系。
- 地理区域。
- 历史事件。
- 组织势力。
- 物品道具。
- 禁忌和限制。
- 文风规则。

### 数据策略

设定库保存为项目内数据。后续可提供“导出为 World Info”或“从 World Info 导入”，但第一版不自动同步。

## 角色库页

### 目标

支持本地角色和 SillyTavern 角色卡引用共存。

### 角色来源

```json
{
  "sourceType": "local",
  "id": "local_hero",
  "name": "主角",
  "tags": ["角色:主角", "主线:复仇"]
}
```

```json
{
  "sourceType": "character-card",
  "id": "Seraphina.png",
  "name": "Seraphina",
  "tags": ["角色:Seraphina"]
}
```

### 本地角色字段

- 姓名。
- 身份。
- 外貌。
- 性格。
- 目标。
- 秘密。
- 当前地点。
- 当前状态。
- 持有物。
- 关系。
- 标签。

### 规则

本地角色不依赖 avatar 文件。引用角色卡时，项目可以保存动态状态，但不自动改写角色卡源文件。

## 世界观页

### 目标

管理项目内世界观条目，并可选绑定 SillyTavern World Info。

### 功能

- 手写 lore entry。
- 标记地点、组织、规则、历史、伏笔。
- 给条目设置重要性。
- 给条目设置适用卷、章、场景和标签。
- 从已有 World Info 导入。
- 绑定已有 World Info 作为检索源。

### 规则

项目内 lore 是小说事实来源之一。World Info 是可选外部素材源。

## 主线 / 支线页

### 目标

维护长篇故事的线路状态。

### 主线

项目开始写作前必须存在一条主线。当前已实现 `validateMainPlotlineRequired()`，UI 应在主线为空时禁用生成入口，并在新建小说页直接提示。

### 支线

支线不是准备期必需项。当前已实现 `canAddSubplot()` 始终允许新增支线。UI 应支持项目后期随时添加支线。

### 线路字段

- 名称。
- 类型：主线或支线。
- 状态：active、paused、resolved、closed。
- 相关角色。
- 相关地点。
- 相关卷章。
- 标签。
- 未兑现承诺。

## 模板与节奏页

### 目标

管理大纲和章节节奏模板。

### 当前实现

当前模板推荐函数根据题材和关键词返回模板名称。

UI 第一版应支持：

- 输入题材。
- 输入关键词。
- 查看推荐模板。
- 查看模板说明。
- 选择主模板。
- 选择辅助模板。

### 后续扩展

后续模板数据应扩展到：

- 升级流/成长流。
- 副本/地图推进流。
- 权谋/势力经营流。
- 悬疑解谜流。
- 感情线/群像关系流。
- 爽文打脸流。
- 多线并进流。

## 卷纲 / 章纲页

### 目标

编辑长篇结构。

### 功能

- 卷列表。
- 章列表。
- 章目标。
- 冲突和转折。
- 出场角色。
- 相关主线和支线。
- 锁定状态。
- 重排。
- 局部重生成入口。

### 当前实现覆盖

当前 `createChapterEditorState()` 提供 `volumeOutline`、`chapterOutline`、`scenes` 状态壳。UI 可先围绕这些状态展示和编辑，后续再接持久化 API。

## 场景页

### 目标

把章节拆为可生成、可审核、可合并的场景。

### 场景字段

- 场景标题。
- 场景目标。
- 出场角色。
- 地点。
- 相关线路。
- 相关标签。
- 目标字数。
- 状态：planned、drafting、done、accepted。

### 规则

逐场景生成是默认路径。整章生成只是快速模式，不应取代场景结构。

## 上下文预览页

### 目标

让用户在生成前看到本次会注入什么、排除什么、用了多少预算。

### 当前实现覆盖

当前 `buildNovelContext()` 返回：

- `included`
- `excluded`
- `used`

UI 第一版应显示三块：

- 已包含上下文。
- 已排除上下文。
- token 使用量。

### 后续扩展字段

后续应显示：

- 来源。
- 选择原因。
- 排除原因。
- 分类预算。
- 用户锁定项。
- 临时指令。

## 写作页

### 目标

独立维护小说正文，不依赖聊天消息。

### 功能

- 当前卷章场景选择。
- 场景草稿。
- 章节草稿。
- 逐场景生成。
- 整章快速生成。
- 合并场景。
- 润色入口。
- 保存草稿。

### 生成策略

调用生成时通过 `getContext()` 使用当前模型和 SillyTavern 生成能力，但上下文由小说项目构建，不从当前聊天历史隐式读取。

如果项目没有绑定任何角色卡或 World Info，生成仍应使用项目内角色库、世界观、主线、大纲和场景信息。

## 章后审核页

### 目标

章节完成后，让 AI 提出状态更新建议，用户确认后才成为项目事实。

### 当前实现覆盖

当前 `createChapterReviewState()` 提供 `status` 和 `notes` 状态壳。UI 第一版应显示审核状态和建议列表。

### 审核类别

- 本章摘要。
- 关键事件。
- 角色状态变化。
- 关系变化。
- 地点变化。
- 组织变化。
- 物品变化。
- 主线推进。
- 支线推进或新增。
- 伏笔新增、揭示或关闭。
- 冲突提示。

### 规则

AI 建议默认不写回。只有用户确认后，才写入项目事实。

## 页面与当前实现覆盖矩阵

| 当前已实现能力 | 页面 | UI 行为 |

| 项目 ID 校验 | 新建小说 | 非法 ID 即时错误 |

## 推荐实施阶段

### 阶段 1：工作台入口与项目创建

- 扩展菜单增加入口。
- 创建右侧抽屉工作台容器。
- 实现“我的小说”和“新建小说”页。
- 支持空白小说创建。
- 支持项目 ID 和主线校验。

### 阶段 2：独立设定与角色库

- 新增项目内设定库。
- 新增项目内角色库。
- 支持本地角色和角色卡引用共存。
- 支持项目内世界观和 World Info 绑定共存。

### 阶段 3：模板、大纲和场景

- 接入模板推荐。
- 实现卷纲、章纲、场景编辑。
- 支持锁定、重排和状态标记。

### 阶段 4：上下文预览

- 接入 Novel Context Builder。
- 显示 included、excluded、used。
- 增加来源、原因和预算分类。

### 阶段 5：写作与审核闭环

- 接入生成能力。
- 保存场景和章节草稿。
- 实现场景合并和润色入口。
- 实现章后审核、确认写回和审计记录。

## 风险与约束

- 不应把当前聊天作为项目必需依赖。
- 不应自动改写源角色卡。
- 不应自动改写源 World Info。
- 不应把未实现的生成和审核能力伪装成已可用功能。
- 项目内本地设定和外部 SillyTavern 资产必须有清晰来源标记。
- 写作页必须能在无当前聊天时运行。

## 自审结论

- 已覆盖“完全从 0 手搓小说”的主路径。
- 当前聊天已降级为可选导入源。
- 角色卡、World Info、memory 和 vectors 均为可选增强，不是项目依赖。
- 页面结构覆盖当前已实现功能，并为后续完整小说 IDE 留出扩展点。
- 未包含 git 操作。

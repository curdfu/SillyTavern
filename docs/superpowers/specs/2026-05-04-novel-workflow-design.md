# 长篇小说章节工作流设计规格

**目标：** 将 SillyTavern 改造成适合长篇小说生成的章节式工作流，同时复用现有角色卡、世界书、当前记忆、向量检索、聊天元数据和生成能力，并从设计上避免小说后期上下文撑爆。

**架构：** 第一版采用“前端扩展壳 + 后端 `/api/novels` 项目 API + 可迁移核心模块”。小说项目作为编排层，保存大纲、已确认动态状态、摘要和上下文筛选元数据；角色卡、世界书、记忆、vectors、chat metadata、生成链路仍引用现有 SillyTavern 能力。

**技术栈：** 现有 SillyTavern Node.js/Express 后端、浏览器 ESM 前端、扩展系统、`getContext()`、extension prompts、World Info、vectors、用户数据目录、Jest、Playwright。

---

## 已确认范围

目标系统是章节式长篇小说工作流。

- 项目创建后必须先有一条主线。
- 支线不是项目准备期的强制项，可以随着创作进度后期添加。
- 卷纲和章纲可以由 AI 生成，但用户必须可以编辑、重排、锁定和维护。
- 卷纲和章纲生成时必须内置多种长篇网络小说参考模板，用户可选择模板、混合模板或自定义模板。
- 章节生成默认按场景逐段生成，同时保留一键整章生成的快速模式。
- 每章完成后，AI 只提出状态更新建议；用户确认后才成为项目事实。
- 系统必须共享 SillyTavern 现有角色卡、World Info、当前记忆、vectors、chat metadata 和生成能力。
- 系统必须避免加载无关上下文。小说后期生成时，只按当前章节、场景、出场角色、相关线路、地点、标签、摘要和 token 预算装载必要资料。

第一版不做：

- 多人协同编辑。
- 替换 SillyTavern 核心聊天 UI。
- 自动改写源角色卡或源世界书。
- 在扩展工作流验证前，把它直接做成核心一级小说 IDE。

## 架构设计

采用推荐方案：扩展壳、后端项目 API、可迁移核心模块。

### 前端

新增小说工作流扩展：`public/scripts/extensions/novel-workflow/`。

扩展负责：

- 项目列表和项目切换。
- 项目准备界面。
- 主线编辑器。
- 可选支线编辑器。
- 卷纲编辑器。
- 章纲编辑器。
- 场景清单编辑器。
- 上下文预览面板。
- 场景/章节生成面板。
- 章后审核面板。

复杂逻辑不要堆在扩展入口文件中，应拆到扩展本地 `src/` 目录，例如：

- `project-store.js`
- `outline-editor.js`
- `thread-editor.js`
- `entity-state-editor.js`
- `context-builder-client.js`
- `context-preview.js`
- `scene-generation.js`
- `chapter-review.js`

扩展通过 `public/scripts/st-context.js` 的 `getContext()` 复用现有生成、token、事件、宏、Slash Command、chat metadata、World Info 和 extension prompt 能力。

### 后端

新增私有 Express 路由：`/api/novels`。

后端负责：

- 小说项目增删改查。
- 项目文件读取与写入。
- 草稿持久化。
- 审核记录持久化。
- 后续可扩展导入/导出。
- 路径安全与用户目录隔离。

小说文件应保存到当前登录用户的数据目录。第一版建议位置为：`request.user.directories.user/novels/<projectId>/`。这样可以避免一开始就修改 `USER_DIRECTORY_TEMPLATE`，等功能形态稳定后再决定是否新增正式 `novels` 目录。

所有文件写入都要采用安全写入模式：校验项目 ID，写入临时文件，然后原子替换目标文件。

### 共享 SillyTavern 资产

小说项目不能成为孤立内容库。

- 角色卡只引用，不复制。项目保存稳定引用和小说侧动态状态。
- World Info 只引用，不复制。项目可以绑定世界书，并可选标记相关 entry 或 tag。
- 当前记忆和 vectors 通过 collection 或检索策略引用。
- chat metadata 和 extension prompts 用于把筛选后的小说上下文注入生成流程。
- 小说项目可以保存项目内覆盖项，但不自动写回源角色卡或源世界书。未来如需同步，必须由用户显式触发。

## 数据模型

每个小说项目是一个目录，内部用聚焦的 JSON 和 Markdown 文件组织。

推荐结构：

```text
user/novels/<projectId>/
  project.json
  outline.json
  threads.json
  entities.json
  summaries.json
  context-index.json
  state-log.jsonl
  drafts/
    volume-<id>/
      chapter-<id>.md
  reviews/
    chapter-<id>.json
```

### `project.json`

保存项目元信息、当前进度、共享资产绑定和默认上下文预算。

```json
{
  "id": "novel_001",
  "title": "长篇小说项目",
  "current": {
    "volumeId": "v1",
    "chapterId": "c3",
    "sceneId": "s2",
    "timelinePosition": "第三天夜晚"
  },
  "bindings": {
    "characters": ["Seraphina.png"],
    "worlds": ["王国设定"],
    "memoryCollections": ["chat-default-user-main"]
  },
  "contextBudget": {
    "totalTokens": 24000,
    "currentTask": 4000,
    "activeCharacters": 5000,
    "threads": 3000,
    "worldInfo": 3000,
    "historySummaries": 5000,
    "styleAndRules": 2000,
    "reserve": 2000
  },
  "createdAt": "2026-05-04T00:00:00.000Z",
  "updatedAt": "2026-05-04T00:00:00.000Z"
}
```

### `outline.json`

保存卷纲、章纲和场景清单。卷纲与章纲可以由 AI 生成，但最终由用户维护。

要求：

- 卷纲条目可重排。
- 章纲条目可重排。
- 场景条目可生成、编辑、锁定、标记完成。
- 整章快速生成和逐场景生成使用同一套 outline 与上下文构建器。

### `outline-templates.json`

保存内置和用户自定义的大纲/章纲参考模板。模板用于辅助 AI 生成卷纲、章纲、场景清单和节奏规划，但不强制用户按模板写作。

第一版应内置适配长篇网络小说的模板类型：

- **升级流/成长流**：适合玄幻、仙侠、异能、职业成长。强调阶段目标、能力提升、资源获取、强敌压迫、突破节点。
- **副本/地图推进流**：适合无限流、游戏、冒险、修仙秘境。强调地图目标、规则、关卡、局部反转、奖励和后续钩子。
- **权谋/势力经营流**：适合历史、宫斗、领主、商战、门派经营。强调势力格局、利益交换、暗线布局、阶段胜负。
- **悬疑解谜流**：适合悬疑、克苏鲁、刑侦、惊悚。强调谜题提出、线索投放、误导、阶段揭示和更大谜团。
- **感情线/群像关系流**：适合言情、都市、群像、角色驱动长篇。强调关系阶段、误会、靠近、冲突、选择和关系状态变化。
- **爽文打脸流**：适合都市、玄幻、反套路。强调压迫、误判、铺垫、爆点、反转、余波和新矛盾。
- **多线并进流**：适合长篇群像、史诗、战争。强调主线牵引、多支线轮转、角色视角切换和阶段汇合。

每个模板应包含：

- 模板名称。
- 适用题材。
- 卷级结构建议。
- 章级节奏建议。
- 场景拆分建议。
- 爽点/悬念/情绪曲线提示。
- 适合追踪的状态字段。
- 推荐上下文标签。

模板示例字段：

```json
{
  "id": "growth-progression",
  "name": "升级流/成长流",
  "scope": ["volume", "chapter", "scene"],
  "genres": ["玄幻", "仙侠", "异能", "职业成长"],
  "volumePattern": ["阶段目标", "压迫来源", "资源线索", "训练/试炼", "强敌冲突", "突破节点", "新地图钩子"],
  "chapterPattern": ["小目标", "阻碍", "尝试", "代价", "阶段收获", "下一章钩子"],
  "scenePattern": ["目标", "冲突", "信息增量", "情绪变化", "悬念"],
  "trackingFields": ["能力阶段", "资源", "敌对势力", "未兑现承诺", "下一突破条件"],
  "recommendedTags": ["主线", "角色", "能力", "资源", "敌人", "伏笔"]
}
```

### `threads.json`

保存主线和可选支线。

规则：

- 项目开始生成前必须有一条主线。
- 项目准备阶段不强制创建支线。
- 支线可以来自章后审核建议、用户手动编辑或显式规划。
- 线路状态支持 `active`、`paused`、`resolved`、`closed`。
- 线路可绑定卷、章、场景、角色、地点和标签。

### `entities.json`

保存小说侧人物、地点、组织、物品的动态状态。

角色卡仍是静态基础设定。`entities.json` 只保存长篇写作过程中的动态状态，例如当前位置、身体状态、心理状态、目标、秘密、持有物和关系。

```json
{
  "characters": {
    "Seraphina.png": {
      "displayName": "Seraphina",
      "currentLocation": "北境边城",
      "physicalState": "左肩受伤，行动受限",
      "mentalState": "怀疑盟友但仍保持克制",
      "goals": ["找到失踪信使", "隐瞒王室血统"],
      "relationships": {
        "Roland.png": {
          "status": "临时盟友",
          "trust": 42,
          "notes": "第二卷第三章后开始互相试探"
        }
      },
      "tags": ["角色:Seraphina", "地点:北境边城", "主线:王室血统"]
    }
  }
}
```

### `summaries.json`

保存已确认摘要和事实。

- 卷摘要。
- 章摘要。
- 场景摘要。
- 已确认关键事件。
- 已确认连续性事实。

后续生成应优先使用摘要和已确认事实，而不是历史章节全文。

### `context-index.json`

保存上下文筛选所需的标签和索引元数据。

必需标签模式：

- `角色:<name>`
- `地点:<name>`
- `主线:<name>`
- `支线:<name>`
- `伏笔:<name>`
- `卷:<id>`
- `章:<id>`
- `时间:<phase>`
- `状态:未解决|已揭示|已关闭`
- `重要性:高|中|低`

### `state-log.jsonl`

追加式审计日志，记录已确认状态变更。

每行记录：

- 时间戳。
- 来源章节或场景。
- 用户确认的变更。
- 受影响文件或实体。
- 可行时记录旧值。

## 生成工作流

### 1. 项目准备

用户创建小说项目，绑定现有角色卡，绑定现有 World Info，可选绑定 memory/vector collection，并创建必需的主线。

支线在准备阶段不是必需项。随着故事推进，用户可以后续添加。

### 2. 大纲规划

用户可以让 AI 基于以下信息生成卷纲和章纲：

- 主线。
- 用户选择的大纲/章纲参考模板。
- 已绑定角色卡。
- 已绑定 World Info。
- 已选择的当前记忆。
- 用户的风格与类型指令。

AI 生成的大纲进入可编辑状态。用户可以编辑、重排、锁定或局部重生成。

大纲规划 UI 应支持：

- 选择一个内置网文模板。
- 选择多个模板并设置主模板与辅助模板。
- 查看模板对卷纲、章纲、场景节奏的影响说明。
- 基于当前作品类型推荐模板。
- 保存用户自定义模板。
- 在不删除已有大纲的情况下切换模板并生成改写建议。

### 3. 场景规划

用户可以把章节拆成多个场景。

每个场景应包含：

- 场景目标。
- 出场角色。
- 地点。
- 相关主线或支线。
- 相关标签。
- 目标输出长度。
- 完成状态。

### 4. 上下文预览

生成前由 Novel Context Builder 筛选上下文。UI 展示：

- 本次注入的上下文项。
- 每项来源。
- 估算 token 成本。
- 被选中的原因。
- 被排除的上下文项。
- 被排除的原因。
- 各类别预算使用量。

用户可以锁定必需项、移除可选项、添加临时指令。

### 5. 场景或章节生成

默认模式逐场景生成。快速模式整章生成。

两种模式都使用同一套上下文筛选管线。快速模式只是把当前任务从单场景切换为整章。

第一版不新增独立模型客户端，应通过 `getContext()` 调用现有 SillyTavern 生成能力。

### 6. 章节合并

多个场景草稿可以合并为章节草稿。

用户可以请求润色：

- 风格统一。
- 节奏调整。
- 连续性清理。
- 对话一致性。
- 场景过渡。

### 7. 章后审核

章节草稿被接受后，AI 提出更新建议：

- 本章摘要。
- 关键事件。
- 角色状态变化。
- 角色关系变化。
- 地点、组织、物品变化。
- 主线推进。
- 支线创建或推进。
- 伏笔新增、揭示或关闭。
- 与已确认状态、角色卡或 World Info 的可能冲突。

建议更新不自动成为事实，必须经过用户确认。

### 8. 确认写回

只有用户确认后的更新才写入：

- `summaries.json`
- `entities.json`
- `threads.json`
- `context-index.json`
- `state-log.jsonl`

AI 建议即使被拒绝，也保留在 `reviews/chapter-<id>.json`，方便后续审计。

## Novel Context Builder

Novel Context Builder 是防止长篇上下文膨胀的核心模块。

### 输入

- 项目 ID。
- 当前卷、章、场景。
- 当前场景或章节目标。
- 用户临时指令。
- 出场角色。
- 当前主线和支线标签。
- 地点标签。
- 当前模型 token 上限。
- 项目上下文预算。

### 上下文层级

构建器按层加载上下文。

#### 必载

- 当前场景目标或整章目标。
- 当前章纲。
- 当前进度。
- 输出风格与格式约束。
- 当前章节已生成场景的前情摘要。

#### 条件加载

- 仅加载当前出场角色。
- 当前出场角色之间的直接关系。
- 当前地点状态。
- 与本章或本场景相关的主线条目。
- 明确绑定到章节、场景、出场角色或标签的支线。
- 相关且未解决的伏笔。

#### 检索加载

- 最近章节摘要。
- 标签匹配的已确认历史事件。
- 匹配当前关键词和项目强制绑定的 World Info 条目。
- 匹配场景目标和活动标签的 memory/vector 检索结果。

#### 默认排除

- 无关角色完整卡。
- 无关 World Info 全量内容。
- 无关支线。
- 未被显式引用的已关闭线路。
- 旧章节全文。
- 当前标签之外的低重要性事实。

### 预算策略

预算类别：

- 当前任务。
- 出场角色。
- 线路。
- World Info。
- 历史摘要。
- 风格与规则。
- 预留。

筛选规则：

- 必载项最先保留。
- 用户锁定项优先级高于自动筛选项。
- 项目按优先级、相关性、最近性和标签匹配度排序。
- 超预算时按顺序降级：全文、详细摘要、短摘要、一句话事实、排除。
- 如果必载项本身超预算，停止生成并要求用户缩小场景或章节范围。

### 输出

构建器返回：

- 有序 prompt 片段。
- 每个片段的来源元数据。
- 每个片段的 token 估算。
- 优先级与选择原因。
- 被排除项与排除原因。
- 预算使用摘要。

该输出同时供生成流程和上下文预览 UI 使用。

## 错误处理

- 保存失败时保留旧文件版本。
- 生成失败时不把失败输出写入已接受草稿。
- 章后审核失败不阻塞章节草稿保存。
- 绑定角色卡、World Info 或记忆引用缺失时显示警告，但项目仍可打开。
- 上下文超预算时自动裁剪可选项；如果必载项超预算，UI 要求用户缩小范围。
- 第一版按单用户本地编辑设计，使用 `updatedAt` 检测陈旧保存并提示覆盖风险。

## 冲突处理

- AI 建议与已确认项目状态冲突时，高亮显示并要求用户手动确认。
- 与源角色卡冲突时，不自动改写角色卡。
- 与源 World Info 冲突时，不自动改写 World Info。
- 生成时项目动态状态优先于源静态资产。
- 同一线路不能同时处于未解决和已关闭状态。
- 同一时间位置下，角色不能无确认地处于两个互斥地点。
- 关系数值和关系描述明显矛盾时提示用户修正。

## 测试策略

### 后端单元测试

- 创建、读取、更新、删除小说项目。
- 拒绝不安全项目 ID 和路径穿越。
- 写入失败时保留旧文件。
- 绑定角色卡或 World Info 缺失时仍能打开项目。
- 草稿和审核文件写入正确项目目录。

### Context Builder 测试

- 必需上下文永远被包含。
- 无关角色被排除。
- 无关支线被排除。
- 已关闭线路在未显式引用时被排除。
- 超预算时可选项按预期顺序降级。
- 用户锁定项优先于自动筛选项。
- 返回排除原因供 UI 展示。

### 前端逻辑测试

- 生成前必须已有主线。
- 支线可以在项目创建后添加。
- 卷纲和章纲可编辑、重排、锁定。
- 场景清单可编辑、重排、标记完成。
- 上下文预览展示注入项、排除项和预算使用。
- AI 审核建议未经确认不会成为项目事实。

### E2E 测试

- 创建项目，绑定角色卡，绑定 World Info，创建主线，生成章纲，生成场景，审核 AI 建议，确认写回，并验证状态更新。
- 打开缺失角色引用的项目，确认显示警告且页面不崩溃。
